AgentBoundary: Operation SilentSignal — Penetration Test FINAL RESULT
====================================================================

FINAL VERDICT: 4 CONFIRMED DEFECTS FOUND AND FIXED (all LOW).
No critical, high, or medium in-scope defect was reproduced.

WHAT WAS TESTED
---------------
A comprehensive adversarial assessment of the final QA-13-01 source
(commit d376300), run on a dedicated branch from a separate worktree.
Every API endpoint, all six tools, all ten frontend pages, session and
tenant rules, approval replay and concurrency, prompt-injection attacks
through a stub provider, filesystem locks, resets, backups, real-mode
job limits, input fuzzing, and supply-chain hygiene were probed with
disposable databases on loopback only. The demo database was preserved
byte-for-byte (SHA-256 ad646b36...3a40 before and after), and nothing
was published, deployed, pushed, or sent anywhere outside this machine.

WHAT WAS GENUINELY FOUND (all fixed, each with a failing-first test)
-------------------------------------------------------------------
P-01 (LOW): The scenario detail endpoint was anonymously readable,
exposing full attack fixtures and the evaluation answer key. It now
requires a lab session. (The scenario list stays public, as previously
decided; lab sessions are self-minted, so this is contract consistency
and defense in depth, not a barrier against a determined local user.)

P-02 (LOW): Duplicate JSON keys in a request body silently collapsed
(last one won), so a launch could execute a different scenario than
the first one shown. Duplicate keys are now rejected with a 400.

P-03 (LOW): A real-mode run cancelled while the model was "thinking",
where the reply carried no tool calls, was recorded as INCONCLUSIVE
instead of CANCELLED, contradicting the cancel endpoint's own promise.
The agent loop now rechecks cancel/budget after text-only replies too.
(The same fix first broke 4 older cancel/budget tests by skipping
batch-discard bookkeeping; it was rescoped and all of those tests pass.)

P-04 (LOW, static-only): The CI workflow had no permissions block. It
now declares read-only contents. CI itself has not run remotely.

WHAT HELD UP (so you know it was actually attacked, not assumed)
---------------------------------------------------------------
- Cross-tenant reads (cases, runs, events, reports, alerts, drafts):
  all denied with no data leaked; the Cedar sentinel never appeared
  outside Cedar scope.
- Approvals: exact-match binding, single use, and 8-way concurrent use
  yielding exactly 1 success.
- Locks: a second process, a symlink alias, and a hardlink alias on one
  database were all refused with the database byte-identical.
- Malicious stub-model output (unapproved close + cross-tenant read):
  denied, 0 forbidden completions, flagship case unchanged.
- 500 malformed dispatcher calls + 250 HTTP fuzz calls: zero crashes,
  zero server errors.
- Scripted A1-A6: all PASS, 0 forbidden, comparisons paired correctly,
  weak CLI A2/A4 correctly FAIL on throwaway databases.

WHAT REMAINS UNTESTED (stated plainly, not hidden)
--------------------------------------------------
- A completed live Ollama PASS trial: NOT RUN (Ollama is not installed
  here). Scripted PASS is not live-model proof.
- Python 3.13, Firefox/WebKit, screen-reader audit, npm audit (registry
  policy), remote CI, Docker, PDF export, disk-full simulation: NOT RUN
  for the environmental reasons detailed in the assessment.
- This is not a claim of zero defects or 100% coverage (statement
  coverage on the final tree is 91%). It is a claim that no known
  reproducible in-scope defect remains open after this round.
