# DECISIONS

1. **Monorepo layout** per spec tree: `backend/` (FastAPI) + `frontend/` (Vite React TS) + `docs/`. Keeps the security engine independently testable from the UI — the UI is an untrusted client.
2. **SQLite via Python stdlib `sqlite3`** with explicit SQL and transactions, instead of SQLAlchemy. Rationale: one less dependency failure mode in an offline lab, full control over "check authorization BEFORE reading/mutating" ordering, and the data model is small. Revisit if Postgres is ever required. Migrations = versioned schema SQL + fixture_version.
3. **Session model:** server-side lab sessions. `POST /lab/session` with an allowlisted persona ID returns an opaque token; the backend — never the model, never tool args — derives actor/tenant from the token. This is a *local lab mechanism, not production SSO* (documented everywhere it appears).
4. **Weak mode is a CLI + env-flag + separate DB only.** The API process literally does not contain a route or body field that enables it. Omissions are named constants so tests can assert exactly which check was removed.
5. **Frontend styling:** design-token CSS implementing the spec palette exactly, + lucide-react icons. Tailwind/shadcn were "preferred" but a hand-rolled token system gives deterministic, dependency-light, accessible output and avoids utility-class bloat; charts are hand-built accessible SVG from real API data (no fabricated series).
6. **Deterministic scripted agent first.** (Updated 2026-10-25: the real-LLM adapter is now fully implemented — backend-only OpenAI-compatible tool calling through the same dispatcher — but live real-model evaluation remains NOT RUN until a provider key is configured; the UI must label scripted runs "SCRIPTED LAB SIMULATION" and real runs "REAL LLM EVALUATION", never mixing them silently.)
7. **Attempted ≠ completed.** The dispatcher writes an audit event at proposal time and updates execution fields only after the policy/approval gate; the evaluator reads DB state, never agent prose.
8. **Experiment admin is a persona-model entitlement, not a request flag (2026-10-25, N-02/N-03).** `incident_commander` — the only persona with both tenants in the server-side model — is the designated cross-tenant curriculum launcher and the only lab-reset authority. No JSON field, URL, or persona-picker choice can grant these powers; the picker only selects among server-defined personas, and the backend enforces the rule.
9. **A5 control evidence is split by viewer (2026-10-25, N-04).** The positive control is real experiment evidence, but Northstar viewers receive only a non-sensitive reference; full control evidence is experiment-admin-only. This preserves both honesty (the control happened and is counted) and tenant confidentiality (no Cedar metadata in Northstar-visible payloads).
10. **Weak mode stays offline (reaffirmed 2026-10-25).** Despite a full web console, the deliberately vulnerable baseline remains CLI-only with an env flag and a disposable DB. A browser/API switch would turn a controlled local experiment into a remotely triggerable vulnerable endpoint, which the threat model forbids.
11. **Browser verification runs on the app host (2026-10-25).** The external automated browser cannot reach localhost-only servers (different loopback host), so Playwright runs on the same machine as the servers, with the headless-shell binary fetched directly when the Playwright CDN is blocked. Screenshots are evidence from that host, not from an external browser.
12. **Clean-control honesty beats a green dashboard (2026-10-25, S7-01/S7-04).** Policy holding and mission completion are separate axes: a gateway-allowed but out-of-mission state change is recorded as `OUT_OF_MISSION` (verdict INCONCLUSIVE), never as a clean PASS and never as a bypass. Likewise there is exactly one authoritative legitimate-completion headline; the old tool-name-only score survives only under the renamed `required_tool_calls_completed` and is never task completion. A discarded proposal (cancel/budget) is a third thing, distinct from both a denial and a completion.
13. **Reset refuses rather than cancels (2026-10-26, E8-01/E8-03).** A global reset while jobs are active returns 409 instead of cancelling-and-joining, because a worker mid-transaction cannot be recalled by an event flag — refusing is the only option that cannot corrupt the ledger. The same lock that admits launches guards the reset, one app worker per database file is enforced by a POSIX flock (a second worker fails fast at startup), and the CLI reset takes the same lock. Concurrency is capped small by default (2 real workers) because each holds a SQLite connection and can block on inference; raising it is an explicit operator choice, not something a burst of requests can do on its own.
14. **Failure must be terminal, and idempotency belongs to the operator (2026-10-26, N9-01–N9-03).** A worker that cannot start is not a queued run waiting for rescue — it is an ERROR with a sanitized class, finalized through fallback connections (worker store, fresh connection, app store) so the ledger never strands a run and reset never blocks forever on a dead job; a thread that never starts says ERROR in the launch response itself. Likewise, a restart recovers both queued and running orphans as INTERRUPTED, because no worker survives a whole-process restart and pretending otherwise blocks the lab. And an idempotency key is meaningless without its principal: the key is scoped by trusted operator persona (same operator + fresh session replays; a different operator never inherits), with TTL, reset invalidation, and stale-result rules (error/cancelled runs launch fresh) — a header string alone must never hand one operator another operator's experiment.
15. **Ownership precedes initialization, and a backup must be proven before it is trusted (2026-10-26, T10-01/T10-02/T10-04).** A process that has not yet won the database lock must not touch the database — not even to "helpfully" repair it — so app-owned stores are now built only inside lifespan, after the flock, and CLI mutating commands take the lock on the path before constructing anything; a denied instance leaves byte-identical state and becomes reusable afterwards. Likewise, a reset backup is not a backup until it is verified: the old raw file copy of an open database was replaced by the sqlite3 online backup API plus integrity/schema/row-count verification and an atomic rename, with session creation and launches refused (retryable 409) during the reset so the snapshot provably sees zero concurrent writers. And generated lab state that can contain session tokens (reset backups, SQLite sidecars) is Git-ignored by narrow patterns, stored with private permissions, and pruned to the newest five — because the most likely leak of a local lab credential is not an attacker, it is an accidental commit.
16. **A download is not finished at headers (2026-10-26, T10-03).** Cancellation tracking for a report download now lasts until the body is consumed and the session is rechecked immediately before the browser is handed the file — because a persona switch in the headers-to-body window previously left the old tenant's report free to complete under the new persona. The abort path and the recheck path are independent defenses: either alone stops the leak in some timings, and only both together stop it in all of them.
